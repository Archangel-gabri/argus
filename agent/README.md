# argus-agent

Тонкий агент трансляции экрана и удалённого управления для Argus.

## Зачем

RDP требует пароль учётной записи ОС и существует только на Windows. Агент ставится по SSH —
а SSH-доступ уже доказывает контроль над машиной, — получает от Argus свой токен, и пароль ОС
из цепочки исчезает совсем. Один протокол на Windows, Linux и macOS.

## Что внутри

| Задача | Как решено |
|---|---|
| Захват | ffmpeg: `ddagrab`/`gdigrab` (Windows), `x11grab`/`kmsgrab` (Linux), `avfoundation` (macOS) |
| Кодирование | NVENC → QSV → AMF → VideoToolbox → VAAPI → libx264, каскадом |
| Транспорт | один WebSocket: бинарные кадры H.264 Annex-B + JSON-управление |
| Ввод | `SendInput` (Windows), `/dev/uinput` (Linux) |
| Декодирование | WebCodecs `VideoDecoder` на стороне Argus — без контейнера и буферизации плеера |

Захват и кодирование делает ffmpeg намеренно: своя реализация под каждую ОС и каждый
аппаратный кодировщик — это чужая многолетняя работа, повторять её незачем.

## Ключевой выбор: выбор варианта по ФАКТУ, а не по железу

Агент не гадает «есть NVIDIA — значит NVENC». Он перебирает варианты и берёт первый, который
реально отдал кадры за 6 секунд. Причина конкретная: известный сбой, когда кодировщик
«создаётся», но картинка не идёт — классический чёрный экран KRdp+NVIDIA на Wayland.
Критерий успеха — кадры, а не код возврата процесса.

## Сборка

```bash
go build ./...                                   # под текущую ОС
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build # кросс-компиляция, cgo не нужен
go test ./...                                    # проверки нарезки кадров и инъекции ввода
```

Бинари для всех платформ лежат в `../resources/agent/` и попадают в сборку Argus —
оттуда провижининг заливает их на устройство по SSH.

## Запуск вручную

```bash
argus-agent --addr 0.0.0.0:47990 --token <токен>
argus-agent --selftest        # что реально работает на этой машине
argus-agent --test-source     # тестовая картинка вместо экрана (проверка тракта без прав захвата)
```

Токен читается из `--token`, `ARGUS_AGENT_TOKEN` или файла (`~/.argus/agent.token`,
`%LOCALAPPDATA%\Argus\agent.token`). Через аргументы командной строки его лучше не передавать:
аргументы процесса видны всей системе.

## Честные ограничения

- **Linux/Wayland: захвата нет.** ffmpeg не умеет захватывать Wayland-сессию, а `kmsgrab`
  требует прав DRM-мастера и на живом сеансе KDE недоступен. Нужен клиент
  `xdg-desktop-portal` + PipeWire — это следующий шаг. На X11 всё работает.
- **macOS: просмотр без управления.** Инъекция ввода требует CGEvent (только через cgo),
  а cgo ломает кросс-компиляцию одной командой. Захват работает, клики — пока нет.
- **macOS: разрешение Screen Recording** система спросит при первом запуске. Обойти нельзя.
- **Windows: Smart App Control блокирует неподписанный агент.** Проверено на живой машине
  (Windows 11 25H2, `VerifiedAndReputablePolicyState = 1`): запуск запрещается политикой ещё
  до выполнения кода — `ApplicationFailedException`. Исключения для отдельного файла политика
  не предусматривает.

  **Правильное решение — подписать агент.** По документации Microsoft: если облачная репутация
  не может уверенно классифицировать программу, SAC смотрит на подпись, и валидная подпись
  сертификатом от центра из доверенного списка Microsoft разрешает запуск. Самоподписанный
  сертификат НЕ подходит — он не выстраивает цепочку к доверенному корню. Доступный вариант
  для проекта — Microsoft Trusted Signing (около $10/мес). Это чинит установку у ВСЕХ
  пользователей, а не только на одной машине.

  Временные варианты для своей машины: перевести SAC в режим оценки (audit — логирует, но не
  блокирует) или выключить. Начиная с обновления от апреля 2026 (KB5083769, приложение
  «Безопасность Windows» от v1000.29554) SAC **включается обратно без переустановки Windows** —
  раньше это было в один конец. Переключатель: Безопасность Windows → Управление приложениями
  и браузером → Параметры Smart App Control; тот же эффект даёт
  `HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy\VerifiedAndReputablePolicyState`
  (0 — выкл, 1 — вкл, 2 — оценка) с перезагрузкой.

  Провижининг определяет эту ситуацию и объясняет варианты, а не отдаёт «exit 1».
- **Windows:** агент запускается задачей планировщика с триггером на вход в систему —
  именно чтобы жить в интерактивной сессии. Служба тут не годится: она попадает в сессию 0,
  где нет рабочего стола и захватывать нечего.
- **ffmpeg** должен быть на целевой машине (или рядом с бинарём агента).

## Безопасность

Агент даёт полный доступ к экрану и вводу, поэтому модель угроз простая: кто дошёл до порта
и знает токен — управляет машиной.

- **Токен** — 32 случайных байта, выдаётся при установке по SSH, лежит файлом с правами 600.
  Через аргументы командной строки не передаётся: они видны всей системе в списке процессов.
- **В строке запроса токена нет.** Поток авторизуется подпротоколом WebSocket
  (`argus.token.<токен>`), потому что URL оседает в логах любого промежуточного узла.
  `/health` дополнительно принимает заголовок `X-Argus-Token`; query там оставлен только
  для ручной диагностики курлом на своей же машине.
- **Origin и Host проверяются.** Кросс-доменные WebSocket-подключения браузер НЕ блокирует —
  отсекать обязан сервер. Иначе вредоносная страница через DNS rebinding (перепривязку своего
  домена на адрес машины) обращается к агенту как «своя». Пускаем только `file://`, `null` или
  отсутствующий Origin, и только когда в Host стоит АДРЕС, а не доменное имя.
- **Транспорт шифрован: только `wss://`/`https://`.** Публичного имени у машины нет, центру
  сертификации взяться неоткуда — поэтому доверие строится как у SSH: агент при первом запуске
  создаёт самоподписанный сертификат, Argus читает его **по SSH** (уже доверенному каналу) и
  закрепляет (TOFU). Дальше проверка TLS работает в обычном режиме, а доверенным корнем
  выступает сам закреплённый сертификат — подменить его нельзя.
  Сертификат помечен `CA:TRUE`: без этого OpenSSL не принимает его как якорь доверия
  («unable to verify the first certificate»). Приватный ключ — с правами 600.
  В Electron то же самое делает `setCertificateVerifyProc`: разрешён РОВНО закреплённый
  сертификат конкретного хоста, всё остальное проходит штатную проверку Chromium.
  Проверка ИМЕНИ хоста отключена осознанно: обращаемся по IP, а он меняется — личность
  подтверждает сертификат, а не адрес.
- **Сеть.** Агент слушает `0.0.0.0` — иначе он не виден в tailnet. На Windows провижининг
  открывает порт правилом фаервола **только для диапазона Tailscale** (100.64.0.0/10).
  На Linux и macOS правило не ставится — ограничьте порт сами, если в вашей локальной сети
  есть посторонние.
- Флаг `--no-tls` существует только для отладки на localhost и в обычной работе не нужен.

## Протокол

```
сервер → клиент   бинарный кадр: [1 байт: 1=ключевой, 0=обычный][H.264 Annex-B]
                  текст JSON: {"type":"hello",...} — версия, источник, кодировщик, fps
                  текст JSON: {"type":"fatal","error":...} — почему поток не пошёл
клиент → сервер   текст JSON: {"type":"mouse","x":0..1,"y":0..1,"buttons":маска}
                              {"type":"wheel","delta":±1}
                              {"type":"key","code":"KeyA","down":true}
```

Координаты мыши нормализованы (0..1): агент знает своё разрешение, клиент — нет, поэтому
любое масштабирование окна и letterbox не сбивают прицел.
