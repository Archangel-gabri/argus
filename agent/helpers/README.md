# Захват экрана на Linux Wayland

Проверено на живой машине: KDE Plasma 6 (kwin_wayland), Arch, NVIDIA. Итог — 30 настоящих
кадров H.264 1920×804 с реального рабочего стола.

## Почему нужен отдельный путь

`x11grab` на Wayland не снимает рабочий стол: композитор не отдаёт картинку X-клиентам.
Единственный поддерживаемый способ — портал `org.freedesktop.portal.ScreenCast`, который
отдаёт поток через PipeWire после явного согласия хозяина машины.

## Что делают эти файлы

- **`portal-screencast.py`** — клиент портала. Открывает сеанс, печатает `NODE=<id>`
  (номер узла PipeWire) и держит сеанс, пока жив. С `persist_mode=2` портал выдаёт токен
  восстановления — он сохраняется в `~/.argus/screencast-token`, и **согласие спрашивается
  только один раз**.
- **`uinput-tap.py`** — точный тычок в точку экрана через `/dev/uinput`. Нужен, чтобы
  подтвердить диалог согласия на машине, к которой мы подключены только по SSH.

## Конвейер после получения узла

```sh
gst-launch-1.0 -q pipewiresrc path=<NODE> always-copy=true \
  ! videoconvert ! videoscale ! video/x-raw,format=I420,width=1920,height=804 \
  ! x264enc tune=zerolatency speed-preset=ultrafast bitrate=8000 key-int-max=60 \
  ! h264parse config-interval=1 ! video/x-h264,stream-format=byte-stream,alignment=au \
  ! fdsink fd=1
```

На выходе — H.264 Annex-B, ровно тот формат, который агент уже умеет резать на кадры
и слать в WebSocket. То есть менять надо только источник, а не транспорт и не декодер.

## Три вещи, которые стоили времени (не наступать снова)

1. **Относительный указатель НЕ попадает в точку.** Композитор пропускает относительные
   перемещения через ускорение, поэтому «сместить на 1541 точку» не значит «оказаться
   в точке 1541». Пока инжектор был обычной мышью, тычки уходили мимо и диалог не
   подтверждался. Абсолютное устройство (как сенсорный экран) ускорению не подвергается —
   и с первого раза попало.
2. **`pkill -f <имя>` убивает саму SSH-сессию**, если это имя встречается в её командной
   строке. Скобочный приём `[i]мя` не помогает, когда имя есть в команде ещё раз. Гасить
   старые процессы только по сохранённому номеру процесса.
3. **Диалог согласия KDE не имеет кнопки «Поделиться»** — подтверждение это тычок по эскизу
   экрана. И он держится, даже если запросивший процесс уже умер: осиротевший диалог
   выглядит живым, но подтверждать в нём нечего.

## Что нужно на машине

`xdg-desktop-portal-kde` (иначе портал некому обслуживать) и `gst-plugin-pipewire`.
На Arch с частично обновлённой системой второй ставится точной версией под установленный
pipewire — из архива, чтобы не тянуть обновление всей звуковой подсистемы.
