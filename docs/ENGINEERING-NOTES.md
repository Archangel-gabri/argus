# Argus — инженерные заметки

> Решения, замеры и подводные камни, оплаченные отладкой на реальном стенде.
> Главный технический документ проекта.

Personal cross-device **command center** — Electron desktop app. Single-user, local-first, security-first.
Переименовано в **Argus** 2026-07-11; дизайн-контракт — Graphite & Ember (`DESIGN.md`,
спек редизайна: `docs/REDESIGN-2026-07.md`).

## What it is
Five modules: **Devices/Servers** (SSH like Termius), **Banks/Finance**, **Subscriptions**,
**Streaming**, **AI Accounts**. Holds real secrets (SSH keys, API keys, logins) locally in an
encrypted **SQLCipher** vault (master password → Argon2id key). Nothing in the cloud.

## Stack
- **Shell**: electron-vite (dev) + electron-builder (AppImage/pacman). Hardened `BrowserWindow`
  (contextIsolation, sandbox, no nodeIntegration). Secrets live **only** in the main process;
  the renderer talks over validated IPC and never sees raw credentials.
- **Renderer**: React 19 · TS · Tailwind v4 (`@theme` tokens in `src/renderer/src/assets/main.css`)
  · Zustand · TanStack Query (polling) · Recharts · lucide-react.
- **Data**: better-sqlite3 + Drizzle + SQLCipher in Electron `userData` (never in the repo).

## Layout
- `src/main/` — Electron main (window, IPC; later: ssh2, vault, integration pollers)
- `src/preload/` — contextBridge API surface (no secrets cross it)
- `src/renderer/src/` — React app: `components/`, `views/`, `store/`, `lib/`, `data/`
- `DESIGN.md` + `design/tokens.json` — visual contract (the approved "Nexus One" spec)

**Экран ПК (Этап 4, 2026-07-25).** Windows-путь: RDP → guacd (Docker `argus-guacd`, loopback:4822) →
guacamole-lite (WS на loopback) → canvas. Креды летят в шифрованном токене, не в URL; NLA + cert-tofu.
Экран живёт в **отдельном окне** (`src/renderer/screen.html` → `ScreenWindow.tsx`): полный экран, свернуть,
закрыть — родные действия ОС; разрешение сеанса едет за размером окна через `sendSize` (`display-update`),
а не растягивается; буфер обмена ПК↔ноут; автореконнект с backoff (кроме ошибок авторизации).
Пароль принимает только `screen:open` в main — окно экрана получает по `screen:claim` лишь порт моста
и токен. **Все окна создаются через `src/main/windows.ts`** — единственное место с hardened
`webPreferences`, чтобы настройки окон не разъезжались.

**Свой агент трансляции (2026-07-27), `agent/` — Go, без cgo.** Ставится по SSH, получает токен,
и пароль учётной записи ОС больше не нужен вообще (RDP остаётся запасным путём). Захват/кодирование
— через ffmpeg (`ddagrab`/`gdigrab`/`x11grab`/`avfoundation`, каскад NVENC→QSV→AMF→VideoToolbox→VAAPI→x264),
транспорт — один WebSocket (бинарные кадры H.264 Annex-B + JSON-ввод), декодирование в Argus —
WebCodecs `VideoDecoder` (без контейнера и буферизации плеера). Провижининг — `src/main/agent.ts`,
клиент — `src/renderer/src/lib/agentClient.ts`. Бинари под 5 платформ — `resources/agent/`.

Проверено на живом стенде: провижининг по SSH ставит и поднимает службу, агент отвечает,
трансляция открывается за **25 мс** (против 5–7 с у RDP), кадры декодируются и рисуются,
инъекция ввода подтверждена round-trip-тестом через ядро (координаты доехали точь-в-точь).

Три вещи, которые стоили отладки:
1. **Вариант захвата выбирается по ФАКТУ кадров, а не по наличию железа** — кодировщик умеет
   «создаться» и молчать (классика KRdp+NVIDIA = чёрный экран). Критерий успеха — кадры за 6с.
2. **Нарезка Annex-B по «новый VCL-NAL = новый кадр» НЕВЕРНА**: x264 с `ultrafast` включает
   slice-threading и режет кадр на слайсы — было 35 «кадров» вместо 7. Граница кадра — слайс
   с `first_mb_in_slice == 0`, то есть старший бит первого байта после NAL-заголовка.
3. **`hello` собирается ДО отдачи первого кадра** — иначе в него уезжают пустые source/encoder.

**Безопасность агента** (по итогам security-review): токен НЕ в URL — поток авторизуется
подпротоколом WebSocket `argus.token.<токен>`; Origin и Host проверяются (кросс-доменный
WebSocket браузер не блокирует — защита от DNS rebinding лежит на сервере); транспорт только
`wss://` с самоподписанным сертификатом, который Argus читает по SSH и закрепляет (TOFU),
дальше проверка TLS обычная, а якорем доверия служит сам сертификат. Сертификат обязан быть
`CA:TRUE`, иначе OpenSSL не примет его как якорь. В Electron — `setCertificateVerifyProc`.
CSP расширен `wss:` ТОЛЬКО для `screen.html`, у основного окна политика прежняя.

Честные пробелы (описаны в `agent/README.md`): macOS — просмотр без управления (CGEvent требует cgo).

**Экран на Wayland доведён (2026-07-30).** Замерено сквозным клиентом на стенде
(3440×1440@144, RTX 3060): было x264 / 2580×1080 / 65 к/с, стало **NVENC / 3440×1440 / 154 к/с**,
медианный промежуток между кадрами 5 мс. Разборы — `docs/research/2026-07-30-*`. Что важно помнить:

1. **Источник отдаёт кадры ТОЛЬКО при изменениях картинки.** «Нет кадров за 6с» — это покой, а не
   поломка, и на этом агент раньше отвергал исправный аппаратный путь. Держит поток
   `keepalive-time=120` у `pipewiresrc` (KWin объявляет переменную частоту, а KPipeWire
   выбрасывает дубликаты — в отчётах доходило до «1 кадр из 10»). Плюс на время проверки агент
   шевелит экран уведомлением — оно же честно сообщает тому, кто за машиной, о подключении.
2. **Частоту кадров в этом конвейере ограничить НЕЛЬЗЯ — проверено трижды.** Договор с источником
   (`framerate=[1/1,60/1]`) роняет переговоры («reason not-negotiated»); `videorate drop-only`
   даёт 1 кадр за 10 с, потому что придерживает кадр для расчёта темпа, — и после включения
   keepalive результат тот же. Закреплено тестом, чтобы попытка №4 упала на проверках.
3. **NVENC принимает BGRx напрямую.** `videoconvert`/`cudaupload` не нужны и втрое дороже: NVENC
   всё равно запускает CUDA-ядро под преобразование. Именно `videoconvert` был горлышком — до
   его удаления отдавали ~100 к/с вместо 144, которые даёт монитор.
4. **Размер и кодек берутся у ПОТОКА, а не из флагов.** Флаги говорили 1920×1080, и на мониторе
   21:9 картинка молча сплющивалась в 16:9. Строка кодека тоже была зашита (`avc1.42E01F` —
   уровень 3.1, это ≈720p) при фактическом уровне 6.0: по ней клиент настраивает декодер, и
   аппаратный вправе отказаться. Теперь профиль/уровень читаются из SPS первого кадра.
5. **SPS/PPS обязаны идти перед КАЖДЫМ ключевым кадром** (`config-interval=-1` +
   `repeat-sequence-header=true`, у NVENC по умолчанию false): WebCodecs в режиме annexb требует
   заголовки внутри ключевого чанка, иначе подключившийся позже клиент не настроит декодер.

**Замок больше не препятствие (2026-07-30).** Владелец считал, что для экрана «надо войти в
систему»; на самом деле сеанс поднимается автовходом, а экран был ЗАПЕРТ — и снимается по SSH
без пароля (`loginctl unlock-session`, `src/main/session.ts`). Тонкости: сеанс ВЫЧИСЛЯЕТСЯ по
признакам (`Class=user`, `Type=wayland|x11|mir`, непустой `Seat`, `Remote=no`, состояние active),
потому что номер меняется после перезагрузки, а первым в списке идёт `Class=manager` от linger;
нулевой код возврата ничего не доказывает (logind лишь рассылает сигнал — проверяем `LockedHint`);
только `unlock-session <ID>`, никогда `unlock-sessions`; `kscreen-doctor --dpms on` на живой
машине падает с core dump и потому не используется. На Windows блокировку снять нечем в принципе.

**Подстройка качества под канал (2026-07-30).** Конвейер живёт внутри клиента портала
(`agent/helpers/portal-stream.py`), а не в отдельном `gst-launch`: только так до кодировщика
можно дотянуться. Каналы разведены — команды JSON в stdin, двоичный H.264 в fd 1 и ничего
кроме него, события JSON в fd 2. Битрейт меняется на живом конвейере (`changeable in PLAYING`),
частота — сбросом кадров в pad-probe **по монотонным часам**: первая попытка считала по меткам
времени буфера и уронила поток до 0.5 к/с. Решение о ступени принимает СЕРВЕР (`agent/quality.go`,
6 тестов): только он знает, сколько отправил, и только он может тронуть кодировщик. Вниз — сразу,
вверх — после 8 секунд спокойствия. Замерено: 10.5 → 1.0 Мбит/с за три ступени. К кадру добавлены
номер и метка времени: без номера потеря в сети неотличима от сброса на сервере, без метки клиент
выдумывал время из расчёта «наверное, 60 к/с». Задержка проверена: `has_b_frames=0`, кадры IPPPP…

**Сторож (2026-07-30, подача снята 2026-08-06).** `src/main/watchdog.ts` + правила в `alerts.ts`
(25 тестов): машина не отвечает, кончается диск (85/93%), подходит ручное продление. Ничего не
опрашивает — читает уже собранное раз в минуту.

**Уведомлений приложение НЕ шлёт и полос тревог не показывает** — решение владельца 06.08.2026.
Канал до дальних нод флапает, и «не отвечает / отвечает / не отвечает» приходило пачками;
уведомление, которое чаще неверно, приучает не смотреть на уведомления вообще. Оценка тревог
осталась, но подача снята: состояние живёт там, где ему место — статус на карточке машины, диск
в метриках, просроченное продление красным прямо в строке подписки, остаток ИИ у своей записи.
Сейчас вычисленные тревоги никто не показывает; если понадобится подача, это отдельное решение,
а не возврат полос.

Грабли, закрытые тестами: «не знаю» ≠ «выключено»; у выключенной машины показания диска
устаревшие; дни до платежа считаются по КАЛЕНДАРНЫМ суткам; первая проверка отложена на 90с.
Признак «продление ручное» — отдельное поле `manual_renewal` в хранилище с галочкой в форме
подписки (раньше здесь было написано, что поля нет, — неправда с момента его появления).

**Экран приветствия показать НЕЛЬЗЯ — вопрос закрыт (2026-07-30).** Проверено: `kmsgrab` от root
даёт «No usable planes found» (проприетарный драйвер NVIDIA не отдаёт плоскости через DRM), то
есть обещание документации ffmpeg про «либо DRM-мастер, либо CAP_SYS_ADMIN» здесь не работает.
На Windows экран блокировки живёт на защищённом рабочем столе; там запасной путь — RDP, но он
заводит СВОЙ сеанс, а не показывает монитор. Правильный ответ — честный текст, он и сделан.

**Окно AI — реестр доступов, моделей и расхода (2026-08-03).** Было «список ключей», стало
реестр: у записи есть ТИП (`subscription` · `api` · `router` · `free-tier` · `local` · `cli-agent`),
аккаунт/почта, план, состояние, указатель «где ещё лежит ключ», дата истечения, лимиты, «кто им
пользуется» и «чем заменить».

Деньги живут ТОЛЬКО в `subscriptions`; AI-запись ссылается на строку по id. Иначе одна и та же
подписка попадала бы в общий расход дважды — и это нельзя было бы заметить глазами.

Цены моделей: вшитый каталог `resources/ai/model-prices.json` (641 модель, отбор из таблицы
LiteLLM скриптом `npm run ai:prices`) + живое обновление у OpenRouter + ручное переопределение
на уровне доступа. Каталог вшит, чтобы расход считался в деньгах СРАЗУ и без сети.

Расход читается из локальных логов (`src/main/ai-usage.ts`), наружу не ходит ничего. Четыре
грабли, каждая закрыта проверкой:

1. **Один ответ лежит в логе Claude Code несколькими строками** — одинаковые `message.id` и
   usage, разные `uuid` (на живом файле 11 записей на 4 ответа). Дедуп по идентификатору
   ОТВЕТА, иначе расход втрое больше настоящего.
2. **У Codex `total_token_usage` накопительный за сессию** — складывать его по событиям значит
   получить квадрат. Считаем по `last_token_usage`.
3. **У Codex `input_tokens` уже включает кэш, а `output_tokens` — размышления.** Проверяется
   арифметикой самого лога: `total = input + output`. Не вычесть кэш — оплатить его дважды и
   по дорогой ставке.
4. **Ставок четыре, а не одна.** Чтение кэша в 10 раз дешевле входа, запись — дороже, часовая
   запись дороже пятиминутной. У агентных сессий кэш — основная доля трафика.

Проход инкрементальный: на файл хранится курсор (размер + mtime + смещение), смещение двигается
только до последнего полного `\n` — хвост без перевода строки это половина записи, которую
допишут. Замерено на машине владельца: Claude Code — $4354 эквивалента за 15 дней (4.9 млрд
токенов, 20064 запроса), Codex — $169 за 22 дня.

**Для подписки токены ≠ деньги.** Claude Max стоит одинаково, сожгли вы на $50 или на $4000,
поэтому цифра подписана как «эквивалент по ценам API» и рядом показана окупаемость ×N. Пороги
пятичасовых окон Anthropic не публикует — показываем потребление в окне, а «осталось N %»
только если владелец сам задал наблюдаемый потолок.

Реестр наполняется из gitignored `ai.local.json` (как `fleet.local.json`): значения ключей в нём
не хранятся — он ссылается на имена переменных в `secrets/env/api-keys.env`, и Argus читает их
при первом засеве. Сторож получил четыре правила (ключ истекает · ключ отвергнут · остаток на
нуле · бесплатный доступ так и не оформлен); вердикты проверок сохраняются в базе, поэтому
сторож по-прежнему НИЧЕГО не опрашивает сам.

**Файлы засева живут в userData (2026-08-04, дополнено 2026-08-06).** Все четыре —
`ai.local.json`, `subs.local.json`, `finance.local.json` и `fleet.local.json` — ищутся в
`app.getPath('userData')` → `app.getAppPath()` → рабочем каталоге (`src/main/seed-file.ts`). В
собранный AppImage они НЕ входят (в сборку кладутся только `out/**` и `package.json`), а рабочий
каталог у него домашний — поэтому установленное приложение раньше засев не выполняло вовсе, и
это было незаметно: данные, засеянные при разработке, уже лежали в хранилище. **После правки
любого `*.local.json` копировать его в `~/.config/argus/`** (права 600), иначе установленная
копия изменений не увидит.

**Квота приходит от провайдера (2026-08-04).** Расход по логам — это расход ОДНОЙ машины, то есть
нижняя оценка расхода аккаунта. Настоящую цифру знает провайдер, и у подписок она лежит за сессией
веб-панели, а не за ключом (ключа у подписки не бывает вовсе). Поэтому `browser-cookies.ts` читает
куки Brave тем же ключом Safe Storage, что и пароли; кука живёт в памяти main на время запроса.

- **Anthropic** `claude.ai/api/organizations/{org}/usage` — окно 5 ч, неделя, недельный лимит на
  отдельную модель, всё в процентах. Организация лежит в самой куке `lastActiveOrg`. Потолка в
  токенах Anthropic не публикует: у среза есть доля и НЕТ знаменателя, подставлять туда токены из
  локальных логов нельзя — числитель был бы с одной машины, знаменатель со всех.
- **Cursor** `cursor.com/api/usage-summary` — тариф и включённый расход. На Free `limit === 0`, и это
  «включённого расхода нет вовсе», а не «нет данных».
- По ключу: **OpenRouter** `/api/v1/credits`, **Firecrawl** `credit-usage` + `token-usage` (два
  разных счётчика), **Tavily** `/usage` (брать `account`, а не `key`).
- Квоту НЕ публикуют: ChatGPT (free), Gemini/AI Studio (панель рисуется закрытым RPC Google), Exa,
  Copilot. Пустой ответ = «не знаем», а не ноль: ноль в полосе читается как «всё цело».

Три грабли, оплаченные отладкой:
1. **Перед значением куки Chromium может стоять SHA-256 её домена, а может не стоять** — зависит от
   версии, которой куку писали. Резать 32 байта вслепую нельзя: на живой базе владельца приписку
   имели 57 записей из 60, у трёх старых так отрезалось бы само значение. Приписка ПРОВЕРЯЕТСЯ на
   равенство `sha256(host_key)`.
2. **Наблюдаемый максимум нельзя считать по текущему периоду** — период сравнивается сам с собой и
   даёт ровно 100 % всегда. На экране это выглядело как «Последние 7 дней 100 %» красным при
   спокойной неделе. Пик берётся только по ЗАВЕРШЁННЫМ периодам.
3. **Адрес для проверки ключа живёт не только на записи.** Ключ Codex выписан сторонним роутером и
   в `api.openai.com` не действует никогда, а после перехода на каналы он лежит в КАНАЛЕ аккаунта
   OpenAI вместе со своим `baseUrl`. Проверка, смотревшая только на запись, объявляла рабочий ключ
   протухшим (`keyEndpointBase()` в `ai.ts`).

Панель расхода роутера (`cli.neutrino.su/usage`, KEEPER) отвергает не-браузерные запросы
(«fetch request required») и не пускает ни по ключу, ни по паролю — расход по роутеру считается по
локальным логам Codex.

**Сроки на удалённые операции (2026-08-06).** Почти всё здесь построено на обратных вызовах, и
если канал «почернел» (соединение живо, данные не идут), вызов не приходит НИКОГДА. Обычной
гонки с таймером мало: она освободит ждущего, но не остановит источник — поздний вызов всё равно
заведёт сессию, которой никто не владеет, или опубликует обрубок под именем настоящего файла.
`src/shared/deadline.ts` — ворота: срок сначала АТОМАРНО забирает право завершить, потом отменяет
источник, и только потом сообщает об ошибке. Всё, что должно случиться при успехе, кладётся
внутрь `settle`; появившееся поздно утилизируется через `discardLate`. Применено к списку каталога
и передаче файлов, открытию терминала, проверке ключей ИИ, опросу бирж, каждому соединению
туннеля, запуску Docker и занятию локального порта. Две ловушки, оплаченные отладкой:
`AbortController` прерывает ожидание заголовков, но НЕ чтение уже полученного тела — поэтому тело
читается внутри срока; и лишний слушатель `close` на каждом соединении туннеля — это утечка,
которую туннель копит сам.

**Ревью 2026-08-05 — что менялось и почему.** Полный проход по приложению.
Самое важное для понимания текущего кода:

1. **Засев применяется ОДИН РАЗ на запись** (`seed_applied`, свой вид у подписок, счетов и ИИ).
   Файлы засева читаются при каждом открытии хранилища, и без этой памяти удалённая запись
   возвращалась при следующем входе, а переименованная — двоилась. Ключ помечается принесённым
   независимо от того, есть запись в базе: иначе у полного хранилища память не наполнится
   вовсе. Обновление сумм из файла осталось — устаревшая цифра хуже отсутствующей.
2. **День списания подписки живёт отдельно от даты** (`renewal_day`). Короткий месяц зажимает
   дату (31 января → 28 февраля), и без отдельного якоря исходное число терялось навсегда.
   Якорь переучивается только явной правкой даты продления.
3. **`OsFamily` знает `'unknown'`** — «спросить не удалось» это не «выключено». Проверять
   достижимость только через `osReachable()`: сравнений с `'off'` в коде быть не должно,
   компилятор их пропуска не ловит.
4. **У каждого вида опроса своя память промахов** (`probe`, `pc-os`, `pc-metrics`). Правило
   «выключено после серии промахов» означает неудачи ОДНОГО опроса подряд; общий счётчик превращал
   один флап канала в приговор.
5. **Деньги форматирует только `money()`**: от тысячи без копеек, ниже — всегда две. Внешнее
   `Math.round` перед ним не ставить — оно превращало расход в 40 центов в «$0».
6. **Логотипы вшиты и МОНОХРОМНЫ** (`assets/brands/catalog.ts`, 36 знаков; сборка —
   `npm run brand:logos`). Опознание компании — `src/shared/brands.ts`, одна карта на все зоны.
   Сервисы «логотип по домену» не подключены намеренно: такой запрос сообщает чужой компании
   весь портфель владельца, а Clearbit, на котором держались все подобные решения, отключён.
   Источников два: simple-icons (CC0) и Wikimedia Commons через Wikidata P154 (нужен внятный
   User-Agent, иначе отказ; лицензия каждого файла проверяется и пишется в каталог, share-alike
   не берём). Знак рисуется **цветом текста** — фирменный `tint` остался ровно у крупного знака
   в панели деталей ИИ: цвет в приложении занят делом, им подписаны состояния, и цветной значок
   в списке читается как «у этого что-то не так». Скрипт идемпотентен и переживает недоступность
   источника — не собравшийся бренд остаётся из прошлого каталога, а не пропадает.
7. **Путь чистого пользователя закреплён e2e** (`e2e/user-journey.e2e.ts`) и идёт через
   `window.api`, а не клики: клик проверяет вёрстку заодно с логикой и падает от неё же.
8. **Растровый логотип красится скриптом, а не CSS** (`tools/monochrome-logo.mjs`, зависимостей
   нет — PNG разбирается через zlib). У четырёх файлов из пяти фон НЕПРОЗРАЧНЫЙ, поэтому
   `filter: invert` дал бы белый квадрат. Скрипт определяет фон по углам, вычитает его и
   оставляет силуэт одной краски; отказывается писать результат при покрытии <1 % или >95 % —
   это признак, что фон определился неверно.
9. **Строки списков — сетка, а не поток.** Бейджи разной ширины между названием и суммой
   заставляли колонки гулять по горизонтали у каждой строки. Подробности живут ПОД названием.
10. **Интерфейс осматривается инструментом** (`npm run ui:lab`): поднимает собранное приложение,
    обходит экраны, снимает и ловит обрезанный текст (`scrollWidth > clientWidth`), английские
    слова, низкий контраст, кнопки меньше 24 пикселей и кнопки без имени. Цепочки цветов с
    `oklab(… / a)` пропускаются намеренно: Tailwind v4 теряет там альфу, и инструмент, который
    врёт, заставляет чинить исправное.
11. **Двойной счёт устраняется САМ, а не кнопкой** (`src/main/spend-link.ts`). Сервер живёт
    двумя записями по замыслу — железкой в парке (с ценой) и платежом в подписках, — и обе
    несут деньги. Приложение находило пары и предлагало связать; это неверно, потому что цифра
    врала до тех пор, пока человек не сделает работу, которую программа уже выполнила. Связь
    ставится при открытии хранилища и при заведении записи, РОВНО ОДИН РАЗ на устройство
    (`seed_applied`, вид `devlink`): разорванную владельцем связь не восстанавливаем, иначе
    спор шёл бы на каждом запуске. Признак пары — `src/shared/duplicate-spend.ts`.
12. **Действие, которого больше нигде нет, не прячется под наведение.** Вход в кабинет банка —
    единственный способ обновить остаток российского счёта, а кнопка появлялась при наведении:
    о самой возможности владелец не знал.

**Скорость парка (2026-07-26).** Замерено на живом стенде: было 68с от входа до появления статусов,
стало 0.85с. Три слоя вместо одного: (1) `listDevices` подмешивает последний снимок из
`metric_snapshots` — сетка рисуется мгновенно; (2) `liveness.ts` — дешёвая проверка живости
раз в 10с; (3) полный SSH-опрос раз в 30с с защитой от наложения проходов.

**Живость проверять ТОЛЬКО по SSH-баннеру, не по факту TCP-коннекта.** На машине владельца поднят
VPN в режиме fake-ip TUN: коннект «успешно» устанавливается к ЛЮБОМУ адресу, и выключенный сервер
показывался онлайн с подозрительно одинаковым откликом 125мс у всех хостов. Ждём `SSH-2.0-…` —
это тот же один round-trip, но подделать его туннель не может. Бюджет **8с** (замер 06.08.2026 на
живом парке: баннер от нью-йоркской ноды идёт 2.60–2.74с, от немецкой 2.43–2.67с; при прежних 4с
запас был 1.3с, и каждый пятый «не отвечает» приложение придумывало само).

Причина отказа решает вердикт: «отказано в соединении» и ответ не-SSH байтами означают, что
машина ОТВЕТИЛА, — это «не знаю», а не «выключено». Если весь парк отвалился разом, приложение
один раз проверяет собственный выход в сеть **TLS-рукопожатием** (голый коннект не годится: при
fake-ip TUN он успешен к любому адресу — проверено на `192.0.2.7`).

**Метрики Windows.** Вкладка «Метрики» рендерит `LiveMetrics`; Windows-ветка её не заполняла, поэтому
у ПК вкладка была пустой при живых цифрах на карточке. Сборщик — `WIN_METRICS_V2_PS` в `pc.ts`,
на `Win32_PerfFormattedData_*` (значения «в секунду» уже посчитаны, второй сэмпл не нужен).
CPU процессов брать из перф-счётчиков: `Get-Process` отдаёт накопленные СЕКУНДЫ, а не проценты.

Два подводных камня, оплаченных кровью (не наступать снова):
1. **Нельзя мешать React и ручной DOM в одном узле.** `replaceChildren()` на контейнере, куда React
   рендерит детей, приводит к `NotFoundError` на следующем удалении → React роняет всё дерево → чёрное
   окно. Canvas монтируется только в лист-узел, куда React не рендерит ничего.
2. **`Guacamole.Client` не пробрасывает ошибки туннеля** — без своего `tunnel.onerror` обрыв WS даёт
   вечный спиннер. И `Guacamole.Mouse` не знает про `display.scale()` — координаты надо делить на масштаб.

**Не-Linux системы (2026-07-29).** Метрики на macOS и FreeBSD собираются своим зондом
(`metrics-bsd.ts`) — там нет `/proc`, поэтому всё берётся из `sysctl`/`vm_stat`/`netstat`.
Порты на них разбираются из `sockstat` (FreeBSD) и `lsof -F` (macOS). Зонд и список портов —
ОДНА команда, которая сама выбирает ветку по `uname -s`: каждый лишний вызов это отдельное
SSH-рукопожатие. Формат ответа определяется по самому ответу, а не по тому, какой ОС мы её
считаем — ошибка в определении дала бы пустой список, а он читается как «ничего нет».
Живых машин с этими ОС нет, поэтому разборщики проверены на образцах реального вывода
(`metrics-bsd.test.ts`, `ports.test.ts`). Полная картина — `docs/OS-MATRIX.md`.

**Переключение ОС (2026-07-29).** Кнопка «Спросить машину» в карточке читает загрузочные
записи прошивки (`bcdedit /enum firmware` / `efibootmgr`) и даёт выбрать нужную. До этого
идентификатор надо было добывать руками, и переключение ОС де-факто не работало. Подводные
камни: вывод bcdedit идёт в кодировке консоли (на русской Windows cp866 → кракозябры, лечится
`chcp 65001` ДО запуска), названия полей переведены (разбор идёт по ФОРМЕ, не по именам полей),
а имена записей одинаковые — различает их только путь загрузчика, поэтому он в подписи первым.

**Честность статусов.** Одна неудача опроса = «не знаю», а не «выключен»: канал до нод флапает,
и на живом парке видно, как нода падает на одном проходе и отвечает на следующем. Выключенной
машина считается с ТРЁХ промахов подряд (06.08.2026: канал до немецкой ноды теряет половину
соединений даже при 15-секундном бюджете, то есть пара промахов там выпадает постоянно).
Одновременные опросы одного устройства склеиваются
в main (`single-flight.ts`) — при открытой карточке по нему независимо работают три опроса.
