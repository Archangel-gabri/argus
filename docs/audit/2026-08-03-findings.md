### `agent/capture.go:308` — Гонка на errBuf: stderr пишется параллельно чтению в текст ошибки

**Домен:** go-агент · **Класс:** leak-race

**Сценарий отказа.** Вариант захвата запускается, живёт, кадров не даёт и пишет в stderr (ffmpeg/GStreamer с предупреждениями — каскад nvenc→vaapi→x264 на машине без NVENC). На 6-й секунде срабатывает ветка `case <-time.After(firstFrameTimeout)` и читает `errBuf.String()` под непрекращающуюся запись сканера. Практический исход в 99% — искажённая/обрезанная строка ошибки; в пределе разорванного чтения slice-заголовка `unsafe.String(unsafe.SliceData(b.buf), len(b.buf))` вернёт новый len со старым ptr, то есть соседние байты кучи. Эта строка уходит в log.Printf (capture.go:132) и, на исчерпании каскада, клиенту в `Fatal.Detail` (server.go:269).

**Доказательство.**

capture.go:201 `var errBuf strings.Builder` — обычный Builder, ни мьютекса, ни канала.
Пишет горутина-сканер, capture.go:239-241:
```
if errBuf.Len() < 4000 {
    errBuf.WriteString(line + "\n")
}
```
Читает главная горутина, capture.go:308:
```
if errText := strings.TrimSpace(errBuf.String()); errText != "" {
    cancel()
```
и ещё на 288, 301, 303, 311, 324, 330, 334. Ребра happens-before нет: `done` пишет ДРУГАЯ горутина (splitAnnexB, capture.go:253), а `cmd.Wait()` закрывает пайп, но НЕ джойнит сканер (в os/exec горутины копирования есть только у формы io.Reader/io.Writer, у StderrPipe их нет).
ВОСПРОИЗВЕДЕНО мной на копии агента (go1.26.4, `go test -race`), вариант `/bin/sh -c 'while :; do echo warn >&2; sleep 0.02; done'`:
```
WARNING: DATA RACE
Read at 0x00c0000b2468 by goroutine 9:
  strings.(*Builder).String()
  ...(*Streamer).runOne() capture.go:308
Previous write at 0x00c0000b2468 by goroutine 11:
  strings.(*Builder).WriteString()
  ...(*Streamer).runOne.func2() capture.go:240
```
Гейт проекта её не ловит: package.json:24 `"test:agent": "cd agent && ... go test ./..."` — без `-race`. При этом сама стратегия (docs/testing/…, гипотеза №11) обещает `-race`.

**Минимальное исправление.** Завести рядом с errBuf мьютекс и один аксессор, не трогая структуру runOne:
```go
var errMu sync.Mutex
var errBuf strings.Builder
errText := func() string { errMu.Lock(); defer errMu.Unlock(); return errBuf.String() }
```
В сканере обернуть запись `errMu.Lock()/Unlock()`, все семь чтений `errBuf.String()` заменить на `errText()`. Плюс добавить `-race` в package.json:24 (`go test -race ./...`), иначе регрессия вернётся молча.
