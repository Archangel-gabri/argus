# Argus — тестовая стратегия (дизайн)

**Дата:** 2026-08-02 · **Статус:** дизайн утверждён владельцем, реализация волнами
**Мандат владельца:** «вся пирамида целиком» — карта + реализация, а не только документ.

---

## 1. Зачем это вообще

Покрытие в проекте сейчас не «неполное», а **перевёрнутое**: 252 теста стерегут мелкие чистые
модули, а больше 200 КБ кода, который распоряжается ключами, деньгами и питанием чужих машин,
не имеет ни одной проверки.

| | покрыто | не покрыто |
|---|---|---|
| `main` | 18 модулей (парсеры, политики) | **19 модулей**: `vault.ts` 53 КБ, `pc.ts` 36, `agent.ts` 34, `ssh.ts` 26, `ipc.ts` 23, `metrics.ts` 10, `sftp.ts` 8, `geo/net/liveness/watchdog/ollama/discovery/sshconfig/windows/lockdown/crypto/index/types` |
| `renderer` | 5 файлов `lib/` + 3 стора | **все** компоненты, панели и views |
| уровни | unit | интеграционные — 0, компонентные — 0, E2E — 0 |

Цена ошибки здесь несимметричная. Баг в парсере `ss` — кривая таблица портов. Баг в
`vault.changePassword` — **безвозвратно потерянный vault**; такой уже был и был найден вручную.
Стратегия строится вокруг этой асимметрии: сначала тесты туда, где ошибка тихая и необратимая.

## 2. Проверенные факты, на которых стоит конструкция

Каждый проверен запуском в этой сессии, не взят из памяти.

1. **`better-sqlite3-multiple-ciphers` собран под Electron-ABI.** Под чистым node v26 —
   `ERR_DLOPEN_FAILED` (модуль грузит биндинг лениво, поэтому голый `require` обманчиво проходит).
2. **Под `ELECTRON_RUN_AS_NODE=1 electron` он полностью работоспособен**: чужой пароль →
   `SQLITE_NOTADB`, свой читает, `PRAGMA rekey` отрабатывает.
3. **vitest сам запускается под electron-as-node** — `ELECTRON_RUN_AS_NODE=1 electron
   ./node_modules/vitest/vitest.mjs run <file>` проходит зелёным. Это и делает интеграционный
   слой vault возможным без выдумывания обвязки.
4. **`projects` в vitest 4.1.10 поддерживаются** — проверено пробным конфигом на двух проектах.
5. **Только 10 из 37 модулей `main` импортируют `electron`.** `pc.ts`, `metrics.ts`, `session.ts`,
   `net.ts`, `sshconfig.ts`, `discovery.ts`, `ollama.ts`, `alerts.ts` тестируемы прямо сейчас.
6. **Docker жив**, контейнер `argus-guacd` поднят и здоров.
7. Playwright-браузеры лежат в `~/.cache/ms-playwright`; для `_electron` они и не нужны —
   он поднимает сам Electron. Нужен только пакет `@playwright/test`.

## 3. Архитектура прогона

**Важная поправка (найдена Codex, подтверждена):** `projects` разделяет конфигурацию, но **не меняет
executable и ABI процесса**. Если vitest стартовал под Node, проект `vault` тоже получит Node ABI и
упрётся в `ERR_DLOPEN_FAILED`. Поэтому это не один прогон с пятью проектами, а **два разных запуска
одного workspace**:

```bash
# лёгкие проекты — под системным Node
vitest run --project unit --project dom
# тяжёлый — под Electron-ABI
ELECTRON_RUN_AS_NODE=1 electron ./node_modules/vitest/vitest.mjs run --project vault
```

`npm test` обязан **явно** перечислять лёгкие проекты: голый `vitest run` утянет и тяжёлые.

| проект | среда | что | команда | бюджет |
|---|---|---|---|---|
| `unit` | node | чистые парсеры и политики | `npm test` | < 1 с |
| `dom` | jsdom + testing-library | компоненты, панели, сторы, a11y | `npm test` | < 10 с |
| `vault` | **отдельный запуск под electron-as-node** | реальный SQLCipher-файл в tmp | `npm run test:vault` | < 30 с |
| `net` | node + Docker | реальный ssh2 против `openssh-server` | `npm run test:net` | ~2 мин |
| `live` | node, за env-флагом | живой флот read-only + внешние API | `npm run test:live` | вручную |

Шов для `vault` дешевле, чем ожидалось: `vault.ts` берёт путь через `app.getPath('userData')`
**лениво**, поэтому достаточно `vi.mock('electron')` с временным каталогом — рефактор не требуется.
Проверено пробой: 4 из 5 тестов зелёные с первого захода.

Сверху: **Playwright `_electron`** (E2E над `out/` + smoke над AppImage) и Go-тесты агента.

`npm run check` = typecheck + unit + dom + go + build (быстрый гейт).
`npm run check:full` = всё, включая vault/net/e2e.

**Почему не один прогон:** быстрый цикл при правке парсера обязан оставаться меньше секунды,
иначе им перестанут пользоваться. **Почему не WebdriverIO:** его преимущество — нативный мобайл,
которого здесь нет; у Playwright есть `electronApp.evaluate()`, пускающий тест прямо в main-процесс.

## 4. Оси проверок

### 4.1 Инварианты безопасности

Ничего этого сейчас не существует, и это ценнее остального вместе взятого.

1. **Матрица утечки секретов** — «класс секрета × приёмник × сток».
   Наивный вариант («сигнальная строка не встречается ни в одном IPC-ответе») **неверен**:
   `screen.ts:406 screenClaim` намеренно отдаёт сессионный токен окну-владельцу, и такой тест
   упал бы на корректном поведении, а исключение токена из проверки открыло бы дыру.
   Оси матрицы: секрет (SSH-ключ / passphrase / пароль устройства / API-ключ ИИ / RDP-пароль /
   токен агента) × приёмник (main-окно, screen-окно) × сток (ответ IPC, событие `wc.send`,
   URL, argv удалённой машины, заголовки, буфер обмена, лог, файл на диске).
   Для каждой клетки — разрешено или запрещено, и тест на обе стороны.
2. **Поверхность preload зафиксирована.** Каналы в `preload/index.ts` ≡ каналы в `ipc.ts`;
   новый канал без ведома — провал. Отдельно: `preload/screen.ts` не содержит `vault`/`devices`/`ssh`
   (сейчас это записано только комментарием-намерением и ничем не удерживается).
   Сравнения множеств строк мало — проверять направление (`invoke`/`send`/событие), арность и
   допустимое окно-отправитель. **Оговорка:** Codex оценивает отсутствие sender-ACL как срочную
   дыру; практически при `contextIsolation: true` и песочном preload renderer не достаёт
   `ipcRenderer` мимо моста, поэтому это защита в глубину, а не P0.
3. **CSP.** Основное окно и `screen.html` собираются как ожидается; второе шире ровно на `wss:`.
4. **Секрет не уезжает в argv удалённой машины.** Регрессия на подтверждённую находку Codex
   `4648590`, где `agent/README.md` описывал одно поведение, а код делал другое.
5. **Секрет не в URL и не в логе** — `ai.ts::checkAccount`.
6. **Пиннинг сертификата агента:** закреплённый → `0`, подменённый → `-3`.
7. **Electronegativity** отдельной командой `npm run audit:electron` — чужой взгляд на те же
   антипаттерны.

### 4.2 Живучесть данных (vault)

- `changePassword`: убивать процесс в случайной точке two-phase commit, N прогонов; после каждого
  `unlock` обязан открыть базу **старым или новым** паролем — но всегда одним из двух.
- Сбой между созданием БД и записью соли (непроверенная находка Codex `e5cb81c`).
- Миграции схемы против зафиксированных старых БД-фикстур.
- Каскад `deleteDevice`: snapshots + links + обнуление висячего `jump_id`.
- `getDeviceConn` отдаёт ключ только при `auth_type='key'`.
- Потолок 200 снапшотов на устройство.

### 4.3 Честность состояния

Продуктовая специфика: приложение не имеет права врать о том, чего не знает.
Новый хост = `unknown`; первый промах = `unknown`, второй = `offline`; jump без измерения ≠ `online`;
offline не тревожит устаревшим disk; таймаут рукопожатия ≠ успех; ни одной mock-суммы в итогах;
реальный exit-код вместо вечного `ok:true`.

### 4.4 Конкурентность и жизненный цикл

**Этой оси в первой редакции карты не было вообще** — не «мало тестов», а отсутствовал класс.
Добавлена по итогам разбора Codex, каждый пункт подтверждён чтением кода.

- **Гонки vault.** `unlock()` ждёт `deriveKeyHex` (Argon2id, ~165 мс замерено) и присваивает `db = d`
  **после**. `lock()` в этом окне обнулит `db`, а завершившийся `unlock` его вернёт — приложение
  окажется разблокированным после блокировки. Мьютекса нет. Второй вариант: два одновременных
  `unlock` открывают два соединения, второе затирает первое (утечка handle).
  Нужны interleaving-тесты `initialize / unlock / changePassword / lock` и сериализация состояния.
- **Смена и удаление устройства во время операции.** `deleteDevice` гасит только форварды
  (`ipc.ts:160`); терминал, SFTP, экран и висящие пробы продолжают работать по уже открытым
  соединениям. `access-epoch` инвалидируется только при глобальном `lock`, не при правке устройства.
- **`singleFlight` нечем сбросить** — работа, начатая до `lock`, доживает и отдаёт результат после.
- **`watchdog.startWatchdog` теряет стартовый таймер** — `setTimeout(check, 90_000)` не сохраняется,
  `stopWatchdog` гасит только интервал.
- **Поздние записи main→renderer** после `lock`/`update`/`delete` не должны менять БД или UI;
  `probeMisses`, `pcMisses`, geo-`inFlight` переживают `lock`.
- **Конкурентный провижининг агента** и частичный успех по шагам (каталог → upload → токен →
  сертификат → служба → selftest → health → локальная запись), с постусловием на каждом.
- **Потеря сети по фазам:** DNS, TCP, SSH-баннер, host-key, auth, открытие канала, середина stdout,
  середина SFTP-загрузки, после атомарного rename, после старта удалённой службы.
- **Ресурсы после 100 циклов** open/fail/close — не через нестабильный `process._getActiveHandles()`,
  а через реестр и попытку повторно занять тот же порт.

### 4.5 Property-based (fast-check)

Свойства, а не примеры:

- **Ни один из девяти парсеров не бросает ни на каком входе** (фуззинг). Этого **мало**: парсер,
  всегда возвращающий нули, пройдёт. Нужны семантические оракулы — валидный маркер найден,
  ключевые величины сохранены, нераспознанный формат даёт `unknown`, а не молчаливый ноль.
- CPU% ∈ [0, 100]; общая загрузка ≈ **взвешенное среднее** по ядрам (не сумма — в первой редакции
  свойство было сформулировано неверно).
- `consumeSshBanner`: **любое разбиение потока на чанки даёт тот же вердикт** — ровно тот случай,
  что уже ловили вживую (`SS` + `H-2.0…`).
- Биллинг: нормализация любого периода в месяц > 0 и не NaN.
- Round-trip `device → vault → device` по не-секретным полям.

### 4.6 Гипотезы к фальсификации

Формулировка — «код утверждает X; вот эксперимент, который это опровергнет».

| # | Гипотеза | Опровергающий эксперимент |
|---|---|---|
| 1 | CPU% честный (дельта `/proc/stat`) | `stress` на 1 ядре из 16 → зонд обязан дать ~6 %, load разойдётся |
| 2 | jump-host применяется во **всех** SSH-путях | 2 контейнера, второй доступен только через первый; гнать probe/exec/sftp/forward/ports/metrics/hardware |
| 3 | lock рвёт **все** живые ресурсы | открыть 4 типа → lock → в main пусто, listener'ы исчезли |
| 4 | обрыв SSH закрывает listener *(находка Codex, не проверена)* | `docker kill` sshd при открытом туннеле |
| 5 | неизвестный `LockedHint` ≠ «открыто» *(находка Codex, не проверена)* | скормить `parseSessions` неизвестное значение |
| 6 | vault переживёт сбой до записи соли *(находка Codex, не проверена)* | kill между шагами |
| 7 | TOFU ловит MITM | пересоздать контейнер с новым host-key → обязано быть предупреждение, не тихий реконнект |

| 11 | Go-агент не течёт за сутки | длинный прогон + `ReadMemStats`, `-race` |
| 12 | агент собирается под 5 платформ без cgo | `build-all.sh` + `file` на артефактах |
| 13 | AppImage жив без libfuse2, SQLCipher распакован | smoke на собранном артефакте |
| 14 | WoL долетает, вердикт питания честный | живой прогон на Castiel (проходил руками 23.07) |

*Раздел 6 добавляет гипотезы, найденные Codex.*

### 4.7 Суррогаты живого железа

**Record/replay.** Снять реальные выводы `ss`, `/proc/stat`, `lscpu`, `nvidia-smi`, `sensors`, `df`,
`efibootmgr`, PowerShell-CIM с живого флота (read-only разрешено владельцем) в
`test/fixtures/probe/<host>-<date>.txt`. После этого парсеры проверяются против того, что
**действительно приходит** с Arch, Ubuntu-VPS и Windows — и флот для этого больше не нужен.

Дополнительно: fake sshd на серверной части `ssh2` для быстрых негативов (обрыв, мусорный баннер,
отказ авторизации), Docker sshd — для правды, локальный HTTP-стенд для внешних API.

### 4.8 Что тестировать не будем

- Массовые пиксельные goldens — вечные анимации, Playwright уже требовал `{force:true}`; будет флак.
  **Уточнение по возражению Codex:** 5–8 детерминированных screenshot-smoke состояний с
  принудительно отключённой анимацией — оставляем, это не то же самое, что попиксельные goldens.
- **Внутренности** guacd / RDP / Guacamole — чужой код. **Но интеграцию Argus с ними тестируем**
  (возражение Codex принято): именно там сейчас пароль сохраняется до проверки NLA, «RDP включён»
  подтверждается ложно, а «только tailnet» ничем не доказано.
- Банковский скрейпинг — решено не делать (`nexus-one`, раздел «НЕ делать»).
- Качество ответов Ollama — недетерминировано. **Но схему ответа, таймаут, приватность и
  поведение на мусорном ответе — тестируем.**
- Прод VPN-ноды — никогда.
- Покрытие ради цифры.

## 5. Порядок волн

Порядок пересобран после разбора Codex: приоритет не «достроить пирамиду», а закрыть P0-сценарии —
потеря vault, утечка секрета, **ошибочная удалённая команда**.

| волна | содержание | снимаемый риск |
|---|---|---|
| 0 | каркас: два запуска vitest, `--project`, Playwright, fast-check, фикстуры; один smoke на нативный модуль | строить всё на неработающем раннере |
| 1 | **D1 (fail-open в ребут) — тест + фикс одним коммитом**; затем D2, D4 | разрушающая команда, тихо мёртвые метрики, неотозванный доступ |
| 2 | vault P0: сериализация жизненного цикла, interleaving `lock`↔`unlock`/`rekey`, именованные точки сбоя, fault injection в миграции, digest + `integrity_check` + отсутствие открытого текста в WAL/journal | потеря или порча хранилища |
| 3 | жизненный цикл доступа: эпоха на устройство, единый реестр ресурсов, порядок при `lock`, матрица утечки секретов | доступ переживает отзыв |
| 4 | удалённые мутации: провижининг и `forget` с реконсиляцией, вердикты питания и загрузки; **ранние Go-тесты** — auth до чтения payload, `Origin`/`Host`, битые кадры, `-race` | ложный успех, дыра в агенте |
| 5 | сеть: детерминированный fake transport и fault-proxy, затем Docker как contract-слой | обрывы и половинчатые закрытия |
| 6 | два E2E-сценария (инициализация→CRUD→lock→unlock; открыть/закрыть удалённую грань), CSP/навигация, smoke AppImage в чистом окружении | «собралось, но не работает» |
| 7 | `dom`/a11y и добор unit + property — по пользовательским веткам и семантическим свойствам, не ради счётчика | недостижимый без мыши CRUD, тихо неверные данные |
| 8 | санированный record/replay и `live`/soak — ручные гейты, **никогда не часть зелёного `check:full`** | смена формата у внешних |

Go уехал из хвоста в волну 4: агент — это TLS/WebSocket-сервер с токеном и удалённым вводом,
его протокольная безопасность важнее добора парсеров.

## 6. Второе мнение (Codex) и реестр найденных дефектов

Прогнаны два независимых прохода Codex (GPT-5.6, усилие `high`): архитектурный — атака на эту
карту, и adversarial — охота за гипотезами. По правилу проекта выводы **верифицированы чтением
кода**, а не приняты на веру.

> **Операционная заметка.** Первый запуск провалился не по вине модели: `codex exec` в фоне без tty
> начинает читать stdin (`Reading additional input from stdin…`) и висит до таймаута. Лечится
> `< /dev/null`. Записано, чтобы не потерять 50 минут повторно.

### 6.1 Подтверждено построчно — реальные дефекты

Обсуждение тестов нашло дефекты **до написания единого теста**.

| # | Дефект | Место | Класс |
|---|---|---|---|
| D1 | `pc:power` **fail-open в перезагрузку**: любое значение кроме `poweroff`/`suspend` превращается в `reboot`. Пустая строка, `null`, опечатка — уводят живую машину в ребут | `ipc.ts:349` | критический, разрушающий |
| D2 | `execOnConn` **не имеет дедлайна после `exec`** (`readyTimeout` покрывает только рукопожатие). Сервер, принявший команду и не закрывший поток, подвешивает промис навсегда; `metricsInFlight` в `devices.ts:198` остаётся `true` — **все последующие опросы молча пропускаются**, UI навечно со старыми числами | `ssh.ts:563`, `devices.ts:198` | высокий, тихий |
| D3 | Фильтр приватных адресов не ловит `169.254.*`, `0.*`, multicast, **IPv4-mapped IPv6** (`::ffff:10.0.0.7`) и **имена хостов** — уходят на `ipwho.is`, раскрывая внутреннюю топологию | `net.ts:37` | приватность |
| D4 | `deleteDevice` гасит **только форварды**; терминал, SFTP, экран и висящие пробы продолжают работать по открытым соединениям | `ipc.ts:160` | доступ не отзывается |
| D5 | Гонка `lock` во время асинхронного `unlock`: `db = d` присваивается **после** Argon2id (~165 мс), поэтому `lock` в этом окне будет отменён завершившимся `unlock` | `vault.ts:423,486` | граница блокировки |

### 6.3 Где Codex переоценил

Отсутствие sender-ACL на каналах он трактует как срочную дыру. Практически при
`contextIsolation: true` и песочном preload renderer не достаёт `ipcRenderer` мимо моста — это
защита в глубину, а не P0. Пункт остаётся, приоритет понижен.
