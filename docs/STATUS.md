# Статус Argus

Здесь лежат датированные заметки о готовности, проверках и внутренних именах. Публичные README
остаются короткой витриной, а этот файл хранит контекст разработки.

## Имена и поставка

- Публичное название продукта, npm-пакета, файла хранилища и AppImage — **Argus**.
- Каталог `Nexus-One` — историческое имя в локальном воркспейсе. Его не переименовывали, чтобы не
  ломать внутренние пути; это не второе название продукта.
- Текущая версия в `package.json` — 0.1.0.
- В `electron-builder.yml` настроена релизная сборка AppImage для Linux x86_64. Пакетов для Windows
  и macOS и канала автообновления пока нет.

## Свежая проверка — 16.10.2026

- `npm test`: **1 330/1 330** unit/DOM-тестов, **103/103** файлов, повторный чистый прогон зелёный.
- Первый прогон на свежем `node_modules/electron` столкнулся с одновременной установкой бинарника;
  один suite не стартовал, а два DOM-теста превысили 5 секунд. После завершения установки тот же
  код прошёл полностью без правок.
- `npm run build`: три бандла Electron собраны. Vite сохранил предупреждение о смешанном
  статическом и динамическом импорте `src/main/remote/sftp.ts`; сборка завершилась успешно.
- `npm run test:e2e`: **17/17** проверок Playwright/Electron в двух файлах, 24,2 с. Прогон выполнен
  из чистой копии отслеживаемого кода в `/tmp`, без игнорируемых seed-файлов владельца; каждый
  Electron-сценарий использовал отдельный временный `userData`.

## Контуры проверки

```bash
npm test             # unit + DOM; без SQLCipher, сети и живых доступов
npm run typecheck    # TypeScript для main/preload и renderer
npm run lint         # ESLint по репозиторию
npm run test:vault   # SQLCipher под ABI Electron
npm run test:net     # интеграция с настоящим sshd в Docker
npm run test:agent   # gofmt, go vet, go test -race
npm run test:e2e     # собранное Electron-приложение во временном userData
npm run test:live    # реальный парк и внешние API; только по явному запуску
npm run check        # typecheck + lint + unit/DOM + Go agent + build
npm run check:full   # check + rebuild + vault + net + E2E
```

`test:vault`, `test:net`, `test:live`, `check:full` и `dist` — разные контуры с разными
предпосылками и побочными эффектами. Успешный `npm run build` не доказывает работу SQLCipher в
установленном AppImage или доступность реального устройства.

## Эксплуатационные заметки из прежнего README

- Мастер-пароль не восстанавливается. При первом запуске это подтверждается отдельно.
- Хранилище — `argus-vault.db` и файл метаданных в Electron `userData`; в репозитории их нет.
- Ключ базы выводится из мастер-пароля через Argon2id. Секреты остаются в main-процессе.
- `fleet.local.json`, `finance.local.json`, `subs.local.json` и `ai.local.json` игнорируются Git.
  Установленный AppImage читает их из своего `userData`, а не из репозитория.
- Нативный SQLCipher после `npm run rebuild` собран под ABI Electron, поэтому `test:vault`
  запускается через Electron, а не обычный Node.js.
- Живость устройства проверяется по SSH-баннеру, а не только по TCP-connect: VPN в fake-IP TUN
  может принимать соединение даже для выключенного адреса.
- Одна ошибка опроса не означает, что устройство выключено. Статус меняется после серии неудач.
- Захват экрана блокировки и экрана приветствия не поддерживается. На macOS Go-агент даёт просмотр
  без управления, потому что сборка без cgo не может использовать CGEvent.
- Расход ИИ по локальным журналам отражает только эту машину и является нижней оценкой аккаунта.
  Для подписок денежный эквивалент токенов по API-ценам не равен фактическому платежу.
- Встроенных LLM, поиска подписок по почте и разбора банковских выписок нет намеренно.
- Пользовательские уведомления и отдельная полоса тревог сняты решением от 06.08.2026: состояние
  показывается на карточках устройств, в метриках и строках подписок.
